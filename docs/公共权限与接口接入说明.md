# 公共权限与接口接入说明

适用范围：A部分第3项公共机制，供B/C/D/E开发自己的业务时使用。已接入真实个人账户接口；任务、动物、领养、回访和附件的对象规则仍由各业务负责人实现。公共机制不会自动推断业务归属，也不会把缺失的模块当作允许。

## 1 能直接复用的入口

| 能力 | 代码位置（相对仓库根目录） | 接入方式 |
| --- | --- | --- |
| 会话身份 | backend/src/main/java/cn/edu/sar/common/web/AccessInterceptor.java | 控制器从current(request).id()获取操作者；受保护API默认必须登录 |
| 当前角色、资格 | common/security/CurrentAccess.java（下文common均指同一Java根包） | load(actor)得到不含密码的Actor；requireRole(actor,"RESCUE_ADMIN")校验角色 |
| 对象权限、字段可见范围 | common/security/ObjectAuthorization.java、ObjectPolicy.java | 每种resourceType注册一个策略Bean；require及project每次重新取角色、调用策略 |
| 明确公开的查询 | common/web/PublicRead.java | 只在批准的GET/HEAD方法标注；不会放行POST/PATCH等写入 |
| 幂等受理 | common/command/IdempotencyService.java | execute将业务写入与成功回执放进同一事务；现用于PATCH /accounts/me |
| 版本冲突 | common/api/Versions.java | 锁定业务记录后Versions.require(expectedVersion,actualVersion) |
| 统一响应与错误 | common/api/ApiResponse.java、BusinessException.java，common/web/GlobalExceptionHandler.java | 返回code、message、requestId、data；前端ApiError保留四者 |
| 服务端时间 | common/config/TimeConfiguration.java | 构造器注入Clock；只使用clock.instant()判断期限，数据库时间以UTC保存 |
| 前端请求与命令 | frontend/src/api/client.ts、commands.ts | request处理会话/CSRF/超时；versionedCommand保存一个操作的请求键、原始版本和内容 |

会话Cookie由浏览器自动发送，HttpOnly，应用代码不读取或保存令牌。角色变化由后端每次重新检查，前端菜单只用于显示。CurrentAccess在写事务内使用账户行锁和角色当前读，事务外及只读事务查询不加写锁。不要在长时间只读事务建立旧快照后执行敏感查询；写入鉴权与变更必须在同一写事务中完成。

## 2 对象权限和字段过滤

每个业务包提供一个实现ObjectPolicy的Spring Bean，resourceType使用稳定且唯一的大写名称，例如TASK、ANIMAL、ADOPTION_APPLICATION、FOLLOWUP、ATTACHMENT。实现decide(actor,objectId,action)，按真实数据库关系决定是否允许，并列出READ时可返回的字段。未知动作返回Decision.deny()。不因是SYSTEM_ADMIN就自动允许所有业务资料。

A. 正常场景：服务端取得操作者，业务方检查“申请人是本人”“当前任务负责人”“当前照护者”等事实；允许后继续业务检查，返回限定DTO。

B. 关系变化：转派、交接、撤销权限后，重新查询当前关系，旧页面和旧通知链接也重新鉴权。写入的检查及更新在同一事务中完成，关系查询使用当前读并锁住相应记录；不能查询后释放锁再修改。

C. 不允许或不可用：没有注册该资源策略返回503 / AUTHORIZATION_UNAVAILABLE；策略拒绝或返回null为403 / OBJECT_FORBIDDEN；身份失效401。策略查询故障继续抛出，统一错误机制返回503，不得捕获后允许。

现有ACCOUNT策略只允许本人READ及UPDATE_PROFILE，其他账户和未知动作均拒绝。GET /accounts/me实际经project过滤；资料更新在每次重试时经require重新检查。

```java
long actor = AccessInterceptor.current(request).id();
objects.require(actor, "ACCOUNT", Long.toString(actor), "UPDATE_PROFILE");
```

`project(actor,type,id,publicDto)`先调用READ策略，再按readableFields白名单复制字段；没列出的联系方式、定位、内部备注等不会返回。传入显式构建的公开DTO，禁止直接序列化数据库实体。工具只允许标量或标量集合；嵌套对象必须另建已过滤DTO，并单独评审其结构。字段中的时间转换成带时区ISO字符串。

公开列表使用`@PublicRead`并只查询已批准披露的数据，随后可调用`projectPublic(type,id,publicDto)`。它仅向策略传入ANONYMOUS和READ_PUBLIC，不读取登录权限；策略必须明确允许该对象公开。公开只读注解不会自动过滤字段、检查发布状态或改变CSRF规则。这些是提供该接口的业务方必须落实的检查。

## 3 幂等命令的事务和锁

调用签名：`execute(actor,action,requestKey,payload,resultClass,authorizeEveryTime,work)`。action由后端固定，例如ACCOUNT.PROFILE.V1，不能取自客户端；响应DTO结构或语义变化时使用新的动作版本。

回执唯一键为“操作者＋动作＋requestKey”。requestKey区分大小写，为8—64位字母、数字、下划线或连字符，前端默认UUID。payload包含影响结果的所有业务参数、目标编号及expectedVersion，不包含requestKey；对象字段顺序不影响摘要，数组顺序会影响。角色等集合由业务方先规范排序，字段缺省值由校验后的DTO统一。

A. 首次成功：锁账户，锁/建立回执，重新检查对象权限，执行业务；保存最小成功DTO，与业务、同事务审计一起提交。返回统一外壳。不要在work里发送邮件、HTTP或其他不可回滚的外部操作。

B. 重复或竞争：同键同参在重新授权后返回首次成功data，不再执行work；每次响应生成新的requestId。同键异参409 / REQUEST_KEY_CONFLICT。不同用户、不同动作的键相互独立。新键带旧版本时409 / VERSION_CONFLICT，data.currentVersion给出当前版本；必须刷新、让用户确认后作为新操作提交。

C. 执行失败：业务、回执、同事务审计一起回滚；失败不会被记成成功。权限撤销、对象归属变化后，即使已有回执也拒绝返回。数据库锁等待或依赖故障统一503，不自动重试；网络超时无法证明后端失败，应保留原命令，允许用户用同键重试。

当前实现为保证锁顺序，同一操作者的通用幂等命令串行执行，不同操作者可并行。这是课程项目的明确取舍，不代表100人认领配额测试已经通过。锁序为操作者账户及其角色→回执→业务对象；业务负责人还需冻结跨模块的对象锁顺序。涉及多个用户或access_admin_guard的操作，必须先共同设计锁序，不能直接嵌套另一幂等命令。已有角色配置等接口尚未改用通用回执，不要自行给它们加请求键就认为已生效。

execute使用REQUIRED事务：无外层事务时负责开启；有外层事务时加入。内部业务服务使用REQUIRED或MANDATORY，不能REQUIRES_NEW独立提交。不要捕获异常并伪造成功结果。回执只保存成功DTO和参数SHA-256，不保存命令原文；不得用于登录、改密等凭据操作，不保存密码、会话、原始申请材料或文件正文。返回敏感对象的业务应选择最小DTO，例如仅对象号、状态和版本。

回执是首次操作快照。若某模块的字段可见范围会随权限变化而收紧，调用方必须在返回前再次按当前策略过滤DTO，或只保存不含敏感内容的编号/状态结果；不能只判断“仍能执行此动作”就直接返回旧的敏感字段。

回执当前长期保留，不自动清理。直接删除会使旧键可能再次执行，若以后增加保留期，需要先定义并拒绝过期键，再制定归档方案。V004是新增迁移，已执行的迁移不改写；V005审计与事件迁移已登记，后续从V006登记。

实现依据：[MySQL 8.0锁定读](https://dev.mysql.com/doc/refman/8.0/en/innodb-locking-reads.html)、[Spring TransactionTemplate](https://docs.spring.io/spring-framework/docs/6.2.x/javadoc-api/org/springframework/transaction/support/TransactionTemplate.html)。

## 4 个人资料接口示例（已经实现）

接口：PATCH /api/v1/accounts/me。调用方为本人账户页面，提供方为AccessController→IdempotencyService→AccessService。请求和返回放在同一个接口条目。

A. 本人修改昵称和联系方式：会话有效、字段和版本合法，锁定本人账户后更新并返回资料，版本增加1。

B. 同键同参重试：复用成功资料快照，版本不再增加。同键异参409；新键旧版本409，并返回currentVersion。

C. 未登录401；不合格字段或缺少requestKey为400；故障503。其他模块不能用前端userId冒充本人。

| 字段 | 方向及约束 | 含义 |
| --- | --- | --- |
| nickname | 请求，2—20字，去除首尾空白后仍校验长度 | 昵称 |
| contact | 请求，字符串，最多100字，可空串 | 本人联系方式 |
| expectedVersion | 请求，非负整数 | 页面读到的版本 |
| requestKey | 请求，8—64位，推荐UUID | 本次操作标识 |
| id、account、nickname、contact、volunteerState、roles、version | 成功data，结构与User一致 | 首次操作的结果快照；当前角色使用GET /accounts/me重新读取 |
| code、message、requestId、data | 每次响应统一外壳 | 错误时保留请求号；冲突可能附currentVersion |

浏览器以HTTPS传JSON，带会话Cookie和X-XSRF-TOKEN。本机开发按现有localhost HTTP配置运行。成功示例正文：

```json
{"nickname":"救助志愿者","contact":"","expectedVersion":0,"requestKey":"682b6781-99cd-4ae8-a787-15af7d916234"}
```

## 5 前端如何调用

```typescript
import { versionedCommand } from './commands'
// User沿用api/access中的类型；version来自读取到的真实对象。
const command = versionedCommand<User>('/accounts/me', { nickname, contact }, version, 'PATCH')
const result = await command.submit()
// 网络失败时保留command，再由用户触发command.submit()；不要重新创建同一操作。
```

工具创建时立即固定JSON正文、版本和UUID。重复点击共享正在执行的Promise；不会自动重放写请求。表单内容变化、新的目标或用户确认了刷新后的状态，才建立新command。实际AccountView已按这个规则接入，后端成功但浏览器丢失响应的情况有真实浏览器测试。

request统一使用站内路径、同源Cookie，自动获取CSRF；10秒超时包含获取CSRF和业务请求，支持外部取消。401触发sar:session-expired清除当前登录状态；400/403/409/503保留message、requestId、data，由页面通过errorText显示。不把请求键、密码或令牌放到localStorage。expectedVersion不会由工具擅自加1，采用后端返回或重新读取的版本。

## 6 浏览、时间和各成员接入验收

已有工作台和公共导航作为0005的入口；B负责线索列表，C负责公开动物列表，当前待接入页面不提供假数据。查询约定沿用page从1开始，pageSize默认20、最大50；后端校验范围并固定排序，返回items、total、page、pageSize。业务筛选项、公开字段和索引由B/C在接口条目中补齐。

所有期限使用构造器注入的Clock。测试可提供`@TestConfiguration`中的`@Primary Clock`，生产配置保持UTC系统时钟。AccessIT已有可推进测试时钟，覆盖锁定及30分钟会话边界；测试时钟不会打入生产JAR。

各成员提交前需证明：本人/他人、角色撤销、对象转派、字段过滤、未知动作、正常提交、同键重复、异参冲突、旧版本、事务失败和依赖不可用等场景。对列表先在SQL中限制可见范围再分页，不允许取全部结果后依赖前端隐藏。下载、统计导出和旧消息跳转也适用相同规则。

这些能力供组员复用；B/C/D/E的策略和真实业务联调尚未完成。暂停资格的ResponsibilityProvider仍需B/C/E接入。T05的通用审计查询和outbox已另行实现，见[审计事件接入说明](审计与事件接入说明.md)；E的消息生成及页面仍待接入，没有将全系统TC/NFR标成通过。
