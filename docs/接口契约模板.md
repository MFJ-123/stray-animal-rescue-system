# 接口契约模板

每个接口复制以下条目填写，提供方和调用方共同评审后合并。不得只给出 URL 而遗漏角色、返回字段或异常结果。请求与响应放在同一条目，保留 A/B/C 场景；这不是已实现的接口清单。

## 接口名称与关联需求

接口名称：待填写。关联 SAR-SYS：待填写。提供方：待填写。调用方：待填写。评审 PR：待填写。

### 调用条件及处理结果

A. 正常场景：操作者角色、对象关系、允许前态、版本及期限检查；成功后的状态与结果。

B. 重复/并发场景：同键同参、同键异参、旧版本、竞争失败；是否复用结果或返回 409。

C. 不允许场景：未登录、无权限、参数错误、条件过期或依赖故障；对应状态码和允许的恢复动作。

### 传递消息定义

| 字段 | 请求或返回 | 类型及是否必填 | 约束及解释 |
| --- | --- | --- | --- |
| 待填写 | 请求 | 待填写 | 包括路径、查询、正文及版本/请求键 |
| 待填写 | 返回 | 待填写 | 列出成功 data 和各错误的字段，不只写“成功” |

统一返回外壳 code、message、requestId、data。操作者由服务端会话确定；编号为字符串，时间带时区。明确空值、枚举、分页和字段可见范围。

### 传输与业务调用

前端页面及调用文件、后端控制器、业务服务、被调用包：待填写。包内 Java 契约写清参数、返回和异常；不要把包间方法误写成必须通过网络调用。
