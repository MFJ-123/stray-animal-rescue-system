# 账户与志愿者资格接入说明

本次实现A的SAR-SYS-0001—0004账户侧功能：注册登录、退出与30分钟闲置失效、资料修改、改密后撤销全部会话、账号与来源登录保护、志愿者申请审核、管理角色配置及资格暂停编排。0005公开业务查询、0006各模块对象授权、完整C7查询运营仍由对应任务接入。

## 角色与登录

注册账号为6至20位字母或数字，服务端规范为小写，唯一索引防止重复。昵称去除首尾空白后为2至20字。密码8至32位、含字母数字，以PBKDF2-HMAC-SHA256加独立随机盐保存；不记录明文密码。联系人仅本人资料接口返回，管理员账户列表不返回联系人。

普通注册只有USER。志愿者审核通过后为ACTIVE并具有VOLUNTEER能力，角色表只保存SYSTEM_ADMIN、RESCUE_ADMIN、ADOPTION_ADMIN管理角色。系统管理员配置管理角色，救助管理员审核及暂停资格，系统管理角色不自动具有救助或领养业务权限。

登录成功设置SAR_SESSION Cookie（HttpOnly、SameSite=Lax，HTTPS下Secure），数据库只保存随机会话令牌的SHA256摘要。用户角色和资格在后续请求重新读取；退出删除当前会话，改密撤销该用户全部会话。所有密码与令牌均不进入响应资料或日志。会话更新不允许已过期记录因并发访问复活。

同一规范化账号连续5次失败锁15分钟，成功清零；不存在的账号也使用相同计数机制和统一失败提示。同一来源固定5分钟窗口最多60次登录尝试。来源使用实际连接地址，不信任任意X-Forwarded-For；如以后增加反向代理，由A明确可信代理策略。失败计数单独提交，不随拒绝登录异常回滚。

## 初始化第一个系统管理员

先准备自己的数据库环境变量。在启动终端设置以下变量，账号与密码都由本机维护者选择，没有仓库默认值：

```powershell
$env:SAR_BOOTSTRAP_ADMIN_ACCOUNT = Read-Host '输入首次管理员账号（6至20位字母数字）'
$secret = Read-Host '输入首次管理员密码（8至32位，含字母数字）' -AsSecureString
$env:SAR_BOOTSTRAP_ADMIN_PASSWORD = [System.Net.NetworkCredential]::new('', $secret).Password
java -jar backend/target/sar.jar
```

仅当数据库尚无系统管理员时创建新账号；不提升已经注册的同名账号，不覆盖已有管理员密码。创建与首次角色授予有审计记录，并通过固定行锁串行化。首次成功后，后续启动可移除这两个变量。

进入 /#/login 登录。若需要体验资格审核，系统管理员先在“管理角色配置”搜索自己的账号，增加“救助管理员”，填写原因并保存，再进入审核入口。至少保留一名系统管理员；角色配置独立于志愿者责任交接。

## HTTP接口和场景

所有路径带 /api/v1 前缀，返回仍为code、message、requestId、data，编号为字符串。写请求先GET /csrf获取令牌，携带X-XSRF-TOKEN；前端公共request工具自动处理。禁止将CSRF令牌或会话令牌放入URL。API控制器默认需登录；匿名例外只有GET /csrf、GET /system/status、POST /accounts、POST /sessions。不存在的API仍返回404。

| 接口 | A 正常场景与结果 | B 重复或冲突 | C 权限与失败 |
| --- | --- | --- | --- |
| POST /accounts | 账号、密码、昵称合法，返回普通用户资料 | 规范化账号重复409 | 字段不合法400；缺少CSRF为403 |
| POST /sessions | account、password正确，设置会话并返回本人资料 | 每次登录生成新令牌，清理当前浏览器的旧令牌 | 凭据/账号锁定统一401；来源超限429 |
| DELETE /sessions/current | 注销当前会话并清除Cookie | 已失效会话401 | 受保护且需CSRF |
| GET /accounts/me | 仅本人完整资料和可用角色 | 每次按当前角色重算 | 失效会话401 |
| PATCH /accounts/me | nickname、contact、expectedVersion更新本人资料 | 旧版本409 | 校验失败400，不接受指定他人身份 |
| POST /accounts/me/password | oldPassword、newPassword、expectedVersion；改密并撤销所有会话 | 旧版本409 | 旧密码错误400，旧会话后续401 |
| GET /accounts | 系统管理员按keyword分页查询账户摘要 | page默认1、pageSize默认20且最多50 | 非系统管理员403，无联系人或密码字段 |
| POST /accounts/{id}/roles | 系统管理员提交roles、reason、expectedVersion，保存管理角色和审计 | 旧版本或移除最后系统管理员409 | 非系统管理员403，非法角色400 |
| POST /volunteer-requests | material、requestKey创建待审核申请 | 同键同参复用；同键异参409；已有待审返回已有记录 | 已有效或已暂停资格409，未登录401 |
| GET /volunteer-requests | 本人分页看申请、状态和审核意见 | review=true由救助管理员查询审核队列 | 用户不能通过参数指定他人身份；越权403 |
| POST /volunteer-requests/{id}/review | 救助管理员提交decision、reason、expectedVersion；通过时同事务授予资格 | 同审核人同决定同意见重试复用；已被不同决定处理409 | 越权403；审批、资格、审计整体提交 |
| GET /volunteers | 救助管理员按账号昵称查询资格 | 使用统一分页及最小账户摘要 | 非救助管理员403 |
| GET /volunteers/{id}/responsibilities | 返回openResponsibilities与unavailableModules | 列出当前阻塞责任，不转移责任 | 未接入模块列为不可用，绝不返回假空清单 |
| POST /volunteers/{id}/suspend | 原因及版本合法，锁资格后再次查清单，全部处理完才暂停 | 未结责任409、旧版本409 | 查询模块缺失或故障503，保持原资格 |

reason为10至500字；material为10至500字。申请状态PENDING/APPROVED/REJECTED；资格NONE/ACTIVE/SUSPENDED。所有更改的操作者从服务端会话获取，前端传userId不能冒充。

## B C E接入责任查询

分别实现domain.access.ResponsibilityProvider为Spring Bean，module分别返回TASK、CARE、FOLLOWUP，findOpen(userId)返回有对象编号和入口的真实清单。TASK同时包含负责人和已确认协作关系，CARE包含照护及相关未结交接，FOLLOWUP包含本人承担的未完成回访。空列表只表示真实查询后无责任；故障应抛异常，不得吞掉后返回空列表。

暂停命令已先锁定account资格行，在同一事务中查询上述服务。B/C/E在认领、指派、转派接收、照护和回访责任分配前，必须在自己的外层事务调用AccessService.lockActiveVolunteer(userId)，再按统一顺序锁业务对象；该方法要求已有事务，避免锁在查询后提前释放。多用户按编号升序锁定。这样可防止“暂停检查为空后又新增责任”的竞争。

本次生产环境没有提供假实现。因此页面可以查询缺失模块及原因，但不会真的暂停；完成零责任、非零责任和故障的分支验证使用的提供者只定义在AccessIT测试配置内。真正接入后还需与B/C/E联合验证配额、权限和锁顺序。

T04进入待评审，T16进入待联调；完整TC和NFR追踪表不因账户测试通过就自动标为全系统通过。E2E的FixtureOnly123只用于一次性CI测试管理员，绝不是部署或本机预览通用密码。
