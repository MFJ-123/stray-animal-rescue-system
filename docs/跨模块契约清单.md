# 跨模块契约清单

这是 G0 需要落实到 Java 接口和 DTO 的业务契约清单，方法名称仅为建议，不代表源码已实现。提供方负责契约与实现，调用方共同评审；具体签名和状态枚举确认后记录在仓库。操作者使用可信服务端上下文，不能直接接受前端伪造的身份。

| 提供方 | 调用方 | 建议服务能力 | 核心输入及返回 | 一致性要求 |
| --- | --- | --- | --- | --- |
| A Access | B/C/D/E | requirePermission、checkVolunteer | 会话上下文、对象与动作；允许或明确拒绝 | 每次写入复查权限，资格暂停与新认领/指派使用一致锁规则 |
| B Clue | B Rescue | getVerifiedClue、markProcessing | 线索编号、版本；核实状态及新状态 | 创建任务时锁主线索；开始执行与线索状态同步 |
| B Rescue | B Clue、A/C | listOpenTasks、cancelTask | 线索/动物/用户编号；未结列表或取消结果 | 通过任务服务取消并保留历史，不外部直接更新 task |
| C AnimalCare | B/D/E | checkAnimal、checkPendingCareTransfer | 动物编号、业务动作；死亡标记、当前责任、条件版本、阻塞项 | 预留/交接/归档时依据当前状态重新检查 |
| C AnimalCare | D/E | finishCareForAdoption、resumeCareAfterReturn | 动物、领养或接回事实、有效接收人；新责任状态 | 加入调用方外层事务，保留照护历史 |
| D Adoption | C/E | releaseReservation、endCurrentAdoption | 申请/领养、已核实事实、原因及版本；处理结果 | 退养与死亡原因区分；同事实重复处理不重复终止 |
| D Adoption | E/C | terminatePendingApplications | 用户或动物、依据及原因；受影响申请/预约清单 | 限制资格、暂停发布等按各自业务规则清理，不能泛化为无条件删除 |
| E FollowUp | D | createVisitsForAdoption | 领养编号、交接时刻；序号1/2/3计划 | 与交接同事务，领养号和序号唯一，重复调用复用结果 |
| E FollowUp | C/D | cancelOpenVisits、checkAdoptionEligibility | 领养/用户及核实事实；取消结果或资格结论 | 保留已完成计划；限制不阻止回访及退养求助 |
| B/C/E | A | listOpenResponsibilities | 志愿者编号；带类型、对象号和入口的未结责任列表 | 暂停前再次检查；每个包只认定自己所属责任 |
| A Operations | B/C/D/E | appendAudit、appendOutbox | 请求上下文、对象、前后状态、原因/事件；登记结果 | 与业务事务一致；消息摘要不含申请原文和密码 |
| 各业务负责人 | E Operations | queryStatistics、resolveRecipients | 统一日期/权限过滤；汇总结果或授权接收人集合 | 查询口径与业务基线一致，通知跳转重新鉴权 |
| C Attachments | B/D/E | bindAttachments、authorizeDownload | 受控草稿或业务对象、附件编号；绑定/授权结果 | 上传者与对象关系、类型/数量检查；私有路径不暴露 |

契约评审时须补齐：谁开启事务、读取时是否加锁、固定锁顺序、重试键和唯一约束、异常传播方式、测试假实现的隔离方式、实际依赖方向。对于互相调用的业务，分别设置不依赖对方编排器的查询/原子操作服务，避免 Spring 依赖循环。

先冻结契约再并行实现。在 G2 只通过正常新用户路径不能证明信用限制已经完成；G3 必须以真实信用与资格实现替换测试假对象，并执行 TC-15、TC-18—21 等边界测试。
