# 需与 A C D E 确认的接口与迁移问题清单

范围为 C2、C3、BE.3.8，供 A/C/D/E 评审。基线 main 为 `7d0d14f`。下列 Java 名称、字段扩展和处理方式以「待定」「建议」标注，只有已经在 main 源码或 V1.1 专项条目定义的签名和字段作为现有约定。评审 PR 均待填写，实测均未运行。现状及证据见[代码与最新基线差距分析表](B模块代码与最新基线差距分析表.md)。[接口契约模板](https://github.com/MFJ-123/stray-animal-rescue-system/blob/7d0d14f/docs/接口契约模板.md)

HTTP 共用 `/api/v1` 和 `code/message/requestId/data`，编号为字符串。未登录 401，越权 403，状态或版本冲突 409，数据库或所需服务不可用 503。内部 Java 接口沿用这些业务结果并由 HTTP 入口映射。所有经办人取可信会话，除服务明确采用可信后台身份外。

## B-01 会话、对象授权与前端路由

**关联需求与职责**　SAR-SYS-0005、0006、0007～0018。A 提供会话、权限框架、统一请求与路由汇总。B 提供对象策略、查询 DTO 和模块路由。提供方与调用方 A/B，评审 PR 待填写。

- **A 正常场景**　公开列表和详情使用独立的公开 GET 和字段白名单。已登录用户或管理员按本人、当前任务关系和职责读取对应视图。
- **B 重复或并发**　取消角色、转派、失去资格后，用旧地址或相同请求键再次访问时，重新检查当前关系和可读字段。
- **C 权限或失败**　匿名写入 401，角色或关系无权 403，不可见详情按约定返回 404。策略或依赖缺失时明确失败。

| 输入与返回 | 字段与约束 |
|---|---|
| Java | `AccessInterceptor.current(request).id()`、`CurrentAccess.load(actorId)`、`ObjectPolicy.decide(actor,objectId,action)`；返回可信身份和可见字段。 |
| HTTP | `GET /api/v1/public/clues` 接收可选区域、物种、状态、关键词、分页参数，返回脱敏 items/total/page/pageSize。受保护列表和详情的最终 URL、过滤字段及隐藏资源错误码请 A/B 确认。 |
| Vue | `request<T>(path,options)` 接收相对业务路径，读 `ApiEnvelope<T>.data`。请 A 明确 `#/clue`、`#/rescue`、管理页和消息跳转的登记方式。 |

**一致性和验收**　鉴权与写入在同一事务。按可见范围筛选后分页，嵌套历史及附件独立过滤。TC-03、TC-12 覆盖匿名公开页、本人/他人、撤权、转派、旧链接和未注册策略。

## B-02 workflow、资格锁与操作原子性

**关联需求与职责**　SAR-SYS-0004、0008、0010、0012～0016。A 提供资格及幂等锁，B 的 BE.3.8 调 C2/C3，D 共同复核数据库读写和索引。A/B/D 评审，涉及动物、附件的命令邀请 C 核对。

- **A 正常场景**　创建、开始、撤回、合并、结案由协调器开启或明确拥有外层事务。C2 负责线索状态和历史，C3 负责任务、参与关系及历史。
- **B 重复或并发**　撤回与认领、结案与建任务、暂停与认领/指派、同时指派或转派同一志愿者竞争。每方在锁保护下重读实际前态、归属、资格、配额及版本。重放重新鉴权。
- **C 权限或失败**　越权拒绝。未结任务阻塞和过期版本返回业务冲突。任一步失败回滚业务、历史、回执、审计和事件。

| 输入与返回 | 字段与约束 |
|---|---|
| HTTP → workflow | 建任务、开始、撤回、合并、结案传目标 ID、动作字段及各自的 expectedVersion/requestKey，返回对象状态、版本及授权范围内的阻塞信息。双对象版本由 A/B 确认。 |
| workflow → C2/C3 | 建议锁定并查询主线索、markProcessing、按线索列未结任务及取消待认领任务。输入为可信 actor、对象 ID 和适用版本，返回状态、新版本、处置结果。方法名和 DTO 待评审。 |
| B → A | `AccessService.lockActiveVolunteer(long) → Account`，MANDATORY；`IdempotencyService.execute(...,authorizeEveryTime,work)`。 |

**一致性和验收**　请 A/D 给出包含操作者/受派人账户、角色、回执、主线索、任务、报名及相关动物/附件的锁顺序表。当前 A 先锁操作者及回执，跨模块文档称先锁主线索。至少确认公共层锁是否计入给定顺序、多个不同账户如何先排序、是否需要 A 提供联合锁入口，以及遇到死锁时 A 现有 503 是否保留或支持同键有限重试。TC-03、04、05、15、16、17 及新增交错竞态和故障注入验证整笔回滚。

## B-03 暂停资格前的任务责任查询

**关联需求与职责**　SAR-SYS-0004、0014、0016，B 提供，A 调用。C/E 同步各自提供方的责任口径。

- **A 正常场景**　返回该用户在未结任务的负责人和有效协作责任。先处理真实阻塞，再由 A 检查并暂停。
- **B 重复或并发**　暂停持有相同用户资格锁后重读。若认领先成功，返回责任；若暂停先成功，新建责任被拒绝。
- **C 权限或失败**　无权查询拒绝。provider 缺失或读取故障导致暂停失败。真实查询为空时返回空列表。

| 输入与返回 | 字段与约束 |
|---|---|
| Java | `ResponsibilityProvider.module() → "TASK"`，`findOpen(long userId) → List<Responsibility>`。 |
| 返回 | `type`、`objectId`、`description`、`path`。请 A/B 确认负责人和协作枚举、路径及待确认报名的阻塞或关闭规则。 |

**一致性和验收**　provider 只读，处置由 C3 命令执行。A 在暂停事务中持资格锁再次查询，测试覆盖已结/未结、旧页面和暂停与新增责任竞争。TC-15、TC-17。

## B-04 认领、报名确认与取消重放

**关联需求与职责**　SAR-SYS-0013、0014、0016、0018。B 提供 HTTP，A 评审公共命令，E 核对取消通知。

- **A 正常场景**　有效志愿者认领或报名，当前负责人确认待确认报名，管理员可取消未终结任务并结束相关报名及关系。
- **B 重复或并发**　认领同键同参重放，异参冲突；确认与撤回仅一方提交。取消同键同参建议复用已授权原结果，新键再取消的状态码和数据仍待定。
- **C 权限或失败**　旧负责人、暂停资格者、代撤回人不能办理对应命令。满额、状态和版本不匹配返回 409；已完成禁止取消。

| 接口 | 请求与成功返回 |
|---|---|
| `POST /api/v1/tasks/{id}/claim` | 任务 expectedVersion、requestKey → taskId、ownerId、state、version。 |
| `POST /api/v1/tasks/{id}/participants` | requestKey → participantId、state、version。 |
| `POST /api/v1/participants/{id}/confirm` | 报名 expectedVersion → participantId、state、version。请确认公共“确认带键”条款是否在此处明确例外，需要时走变更。 |
| `POST /api/v1/tasks/{id}/cancel` | reason、任务 expectedVersion、适用的 requestKey → 任务编号、CANCELLED、新版本。重复取消冲突体和允许的回放状态待定。 |

**一致性和验收**　以具体接口条目校正旧草稿并以最小合法 JSON 做真实 HTTP 验证。请确认 409 返回的 task/participant 状态字段与 A 的 currentVersion 能否同时携带。取消清理和通知同一事务留事实，重复无额外事件。TC-04、16、17。

## B-05 附件上传、绑定与下载

**关联需求与职责**　SAR-SYS-0006～0008、0015。C 提供附件，B 提供线索/任务所属关系和对象授权。

- **A 正常场景**　上报者绑定本人已上传的草稿附件，补充和进度按允许数量追加。具有对象读取权限时可访问原件，公开页面取得授权公开副本。
- **B 重复或并发**　同请求重放复用绑定。附件并发绑定或转派后访问时，重查归属及当前权限。
- **C 权限或失败**　他人草稿、已失效附件、不合格文件及未公开原件拒绝。任何绑定失败使该业务提交回滚。

| 方向 | 字段与约束 |
|---|---|
| HTTP 上传 | `POST /api/v1/attachments` 以 multipart/form-data 上传。附件编号、草稿归属字段和错误 DTO 由 C 确认。 |
| Java 绑定 | 建议可信 actorId、objectType、objectId、attachmentIds[] → 已绑定附件编号。CLUE、线索补充、任务进度的对象类型及草稿旧类型 CLUE_HISTORY/TASK_ENTRY 的处理由 B/C 确定。 |
| HTTP 下载 | `GET /api/v1/attachments/{id}` → 授权文件流或错误 JSON。公开副本和物理存储名映射由 C 提供。 |

**一致性和验收**　绑定的数据库部分加入 B 外层事务，商定文件暂存、数据库回滚和失败清理边界。TC-02、TC-05、TC-12，包括 1/6/0/7 张、错误归属、替换编号、撤权及回滚。

## B-06 动物关联、结果提交与归档

**关联需求与职责**　SAR-SYS-0017、0019、0024。C 提供动物状态和授权，B 持有 task_animal 和任务处置，A/D 评审锁顺序及 FK。

- **A 正常场景**　负责人提交合法的动物编号集合或未建档原因，管理员验收。C 归档时查询 B 未结任务，B 负责处置本包记录。
- **B 重复或并发**　同一任务/动物关系唯一。关联、验收和死亡核实并发时重验当前状态和权限，避免把已失效的检查当作本次确认。
- **C 权限或失败**　任一动物不存在或无关联权限则整体拒绝。未建档路径保留原因。归档需先取得并处置有效阻塞，依赖失败向调用方传播。

| 方向 | 字段与约束 |
|---|---|
| 结果 HTTP | `POST /api/v1/tasks/{id}/result` 传 kind、detail、expectedVersion、animalIds 或 missingReason，返回任务状态及版本。字段来自 V1.1 明细。部分动物已建档、部分未建档的表示由 B/C 确认。还需明确退回后新结果对应的动物快照以及历史关联是否仍保留。 |
| 关联 HTTP | V1.1 另列 `POST /api/v1/tasks/{id}/animals`，输入 animalId、expectedVersion，经办为救助管理员。请确认与负责人提交结果的共用底层服务、重复关联以及允许前态。 |
| Java | C 的 checkAnimal 输入可信操作者、动物 ID、动作，返回存在性、当前状态、访问权及适用版本。B 的 listOpenTasksForAnimal/cancelTask 返回任务阻塞或正确处置结果。签名和失败类型由双方确认。 |

**一致性和验收**　请 C 明确提交结果与最终验收分别检查什么，冻结动物锁、任务锁和关联写入的顺序。B 事务只写 B 所属数据，保留真实档案及历史。TC-05、TC-18、TC-19，覆盖部分无权、未建档原因、重复关联、退回重提与归档竞争。

## B-07 物理模型与 Flyway 版本

**关联需求与职责**　SAR-SYS-0007～0018、0019、0040。D 登记迁移与复核，A 管统一启动，B/C 各写所属表及关联的获准迁移。

- **A 正常场景**　先创建依赖表，再迁移线索、任务和关联，所有迁移从空库与 V005 现有库执行成功。
- **B 重复或并发**　重复启动验证 Flyway 历史。未结主线索和有效报名的唯一性有数据库约束与事务配合。已有共享迁移通过新增版本修复。
- **C 拒绝或失败**　依赖缺失、旧库存在孤儿引用、类型不一致或旧数据重复时，迁移给出明确失败。检查 MySQL DDL 已执行部分及 Flyway 状态后按批准的恢复步骤处理。

| 输入与返回 | 字段与约束 |
|---|---|
| 登记 | 当前 V001～V005 已登记，**从 V006 申请**。提供脚本名、作者、依赖版本、影响表、PR、是否已执行，编号由 D 确认。 |
| 类型及账户 FK | V002 提供 account。请确定 animal_type 的提供者、迁移号、未知物种编号。clue.type_id 依赖此表。确认 BIGINT signedness、状态枚举、长度与索引。 |
| 动物 FK | B 创建 task_animal，C 创建 animal。若动物表晚于 B，B 的后续 ALTER 排在二者之后。D 确认 animal 是否也依赖 B 任务及拆分编号，禁止依赖循环。 |
| 历史字段 | D/B 确认 clue_review、task_progress、open_clue_id 的正式 DDL，以及进度确认、公开摘要、重开等待、负责人历史等必要字段。个人草稿数据库如有需保留数据，另报旧列映射、回填及核对方案。 |

**一致性和验收**　验证目标 MySQL 8.0.46 / InnoDB，采集 `SELECT VERSION()`、Flyway 记录、`SHOW CREATE TABLE`、FK 和唯一索引证据。覆盖空库与 V005 升级、无孤儿关联、终态生成 NULL 后可再建任务、活跃报名历史保留及 100 请求竞争。TC-04、TC-13、TC-17。只在测试库验证，本次未运行。

## B-08 审计、事件与未认领提醒

**关联需求与职责**　SAR-SYS-0009、0011、0015～0018、0036、0039。A 提供审计和 outbox，B 发布事件及提供业务事实查询，E 消费。

- **A 正常场景**　B 同场景提交业务、审计和所需事件。E 按事件引用读脱敏事实并生成站内消息；公开关注进展仅发送给符合披露规则的接收人。后台用 Clock 检查满 24 小时的未认领任务。
- **B 重复或并发**　同一事实复用稳定 eventKey，E 对同一事件和收件人去重。A 的接入说明以 event_id + recipient_id 为物理键示例，V1.1 以 event_key + recipient_id 表达，须由 E/D 冻结落库字段及测试。已取消关注者不再收到新的关注消息。退回待认领后按任务还是按等待轮次提醒由 A/B/E 决定。
- **C 权限或失败**　事务内发布失败回滚，消费失败经 A 的 outbox 重试。过期消息链接重新鉴权。空合法接收人集合应由真实查询得出。

| 方向 | 字段与约束 |
|---|---|
| B → A | `AuditWriter.append(Change) → long`；`OutboxService.append(key,type,objectType,objectId,Map<String,String>) → Event`。RESCUE 模块，动作大写，payload 仅正数 ID、状态码和 version。后台审计可用系统 actorId=0，事件使用 auditId/taskId 等正数引用。 |
| E → B | 建议用 eventKey、auditId 和业务对象编号解析变更发生时的候选人、当前合法接收人和脱敏摘要。转派、取消的旧参与者需依据已留历史，消息正文和接收人数组由 E 自己持有。 |
| Jobs | 仅服务端 Clock、待认领起点和任务当前状态。成功结果为扫描/登记数量或引用，事件键和等待轮次规则待定。草稿转派时更新 open_since 但保留 reminded_at，当前效果偏向每任务一次。 |

**一致性和验收**　不让 B 直接写站内消息。请 E 确认事件类型、动作映射、公开里程碑的接收人、通知路径及重试后的去重。TC-05、TC-11、TC-12、TC-16、NFR-06，含并行补扫、已退订关注者、转派或取消后的旧链接和故障重试。

## B-09 线索和任务的统计查询

**关联需求与职责**　SAR-SYS-0012、0018、0038。B 提供聚合查询，E 负责统计/导出及权限入口，A 复核权限。

- **A 正常场景**　E 根据操作者和筛选范围调用 B 的统计查询，概要与导出使用相同口径。
- **B 重复或并发**　确认时间边界与同次汇总的一致读。明确重复线索、取消任务、验收退回和最终完成各自计数，防止重复计算。
- **C 权限或失败**　未知指标、倒置时间或无权范围拒绝，查询故障明确报错。

| 输入与返回 | 字段与约束 |
|---|---|
| Java | 建议可信 actor、指标、fromInclusive、toExclusive、区域及授权范围 → 各指标数值。由 Asia/Shanghai 区间换算，数据库 UTC。 |
| 现有草稿 | `RescueQueries.workload(Instant,Instant)` 只有上报数与验收数。E 确认结案按结案日期、验收按完成日期等口径，注明取消、合并、撤回、驳回及救助成功如何划分。 |

**一致性和验收**　只读查询，统计与导出使用同一筛选及权限限制。TC-11 验证汇总、导出、日期边界及脱敏。
