# 基础工程接入说明

本次对应 A 的公共工程任务 T02。版本为 JDK17、Spring Boot3.5.16、Maven3.9.11、MySQL8.0.46、Node24.22.1、npm11.6.2、Vue3.5.45、Vue Router4.6.4、Vite8.3.8、TypeScript5.9.3、Vitest5.1.0、Playwright1.65.1。确切依赖由 pom.xml、Wrapper 和 package-lock.json 锁定。

## 模块接入步骤

1. 从最新 main 建功能分支，先按 README 启动，确认数据库连接成功。
2. 前端在 views/<业务包> 添加页面，api 下增加请求文件，复用公共 request<T>；router/modules 增加路由文件，由 A 协调汇总，替换该模块说明页。
3. 后端在 web/<业务包>、domain/<业务包>、persistence/<业务包> 分别添加控制器、业务服务和仓储；包名沿用 access、clue、rescue、animalcare、adoption、followup、operations。
4. 控制器解析请求并校验字段，返回 ApiResponse.success(data, request)。状态、权限和事务在业务服务决定，SQL 在持久化层。
5. SQL 只放 db/migration。V001 为基础记录，D 从 V002 继续登记。各人使用本机开发库及单独测试库，不拼接全库导出。
6. 补齐契约和相关测试后提交 PR。账户鉴权已接入，业务接口默认需登录；公开只读接口需由A审查后明确加入匿名白名单，业务对象仍要由所属模块授权。

## 公共约定

接口统一 /api/v1，响应 code、message、requestId、data，成功 code 为 OK；RequestIdFilter 生成服务端请求号，正文与 X-Request-Id 一致。编号通过 JSON 传字符串。

BusinessException 承载明确的4xx业务失败，GlobalExceptionHandler 统一参数400、业务401/403/409、未知接口404、方法405、数据库503和异常500。参数字段错误位于 data.fields。登录、账户角色和本模块版本控制已实现；其他业务对象授权与通用服务端幂等仍按各任务补充。

前端 ApiError 保留状态码、业务码、data 和请求号；401 发送 sar:session-expired 事件，账户状态随即清除；写请求自动获取CSRF令牌。页面保存同一次操作的 requestKey，网络原样重试复用；公共客户端不自动重试写请求，不自动替调用方生成新键。

服务层注入 Clock，默认UTC，测试可固定时钟。接口时间为带时区的ISO时间，业务展示按Asia/Shanghai；自然日期限按需求定义计算。数据库连接统一UTC。

## 基础连接接口

GET /api/v1/system/status，无业务参数。A：数据库版本和基础记录可读，返回 service=UP、database=CONNECTED、databaseVersion、foundationVersion、checkedAt。B：数据库或SQL失败返回503及请求号。C：未知API返回统一404，不转成前端页面。

该接口是无需登录的基础自检，不包含密码、主机地址、申请或个人资料；其权限设计不能直接套到后续业务接口。

## 验证与阶段边界

mvnw test 不依赖数据库；-Pmysql-it verify 使用真实MySQL8.0.46专用库，验证SQL、HTTP和重复迁移；CI使用一次性容器。浏览器测试正常场景连接真实后端，只有失败展示场景拦截503后再恢复真实调用。

完整G1还包括账户和附件等任务，T02完成不代表G1整体通过。21项TC、10项NFR、正式HTTPS信任及业务备份恢复仍需后续实现后验收。
